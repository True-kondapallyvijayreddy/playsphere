# Stats Hub (Personal + Club Stats) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a single "Stats" entry point branching into the existing player career-stats flow and a new club-stats flow (club list → sport → club record/tally/leaders/matches → the existing match-detail screen), backed by a fix to a real data gap this plan discovered: player tallies have never actually been written.

**Architecture:** Mirror the player career-stats pattern (`users/{uid}/career_stats/{sportId}`, written by the `onMatchSettled` Cloud Function trigger, read by a Dart repository/provider/screen chain) for a new club-scoped collection (`orgs/{orgId}/career_stats/{sportId}`), plus a new precomputed, scheduled global leaderboard (`leaderboards/{sportId}__{statKey}`) for "who leads this stat across the whole app." All new server-side aggregation logic is written as small, pure, unit-tested JS functions (mirroring `contribution.js`/`talent.js`), wired into thin I/O wrappers — nothing here invents a new architectural pattern.

**Tech Stack:** Flutter/Dart (Riverpod, go_router), Firebase Cloud Functions v2 (Node 22, ES modules), Cloud Firestore + Security Rules, `node --test` for JS unit tests, `flutter test` for Dart unit/widget tests, `firebase emulators:exec` for rules tests.

## Global Constraints

- Full spec: `docs/superpowers/specs/2026-08-09-stats-hub-design.md`. Read it before starting — this plan does not repeat its rationale, only its decisions.
- Club stats carry **no** Won/Lost/Drawn — only `matchesPlayed` and `tally`. See spec's "Club Won/Lost is out of scope" section. Do not add W/L fields to `orgs/{orgId}/career_stats`.
- Headline-stat leaderboards exist only for the sports listed in `sportHeadlineStats` (Task 5) / `HEADLINE_STATS` (Task 9) — mind sports (chess, carrom) and performance sports (athletics, swimming) are deliberately excluded, as is the "Other sport" catch-all. Do not add entries for them without a new design decision.
- Global leaderboards include only players with `profileVisibility == 'public'` and `isMinor == false` — mirrors the privacy posture already established for `talentBoards` in `functions/talent.js`. Never widen this without an explicit decision — it is a minor-safety boundary, not a style choice.
- Every new Firestore write path is server-only (Admin SDK / Cloud Functions). No task adds a client write path to `career_stats` or `leaderboards` — `firestore.rules` must keep `allow write: if false` on both.
- Follow existing patterns exactly where one already exists for the thing being built: `CareerRepository`/`CareerLine` for `OrgCareerRepository`/`OrgCareerStats`; `talent.js`'s `buildBoards`/`publishBoards`/scheduled+callable pair for the new leaderboard functions; `player_sport_screen.dart`'s layout for `ClubSportStatsScreen`. Where a task says "mirrors X", read X first.

Create `functions/career.js`:

```js
/**
 * Per-match tally extraction, server-side.
 *
 * Mirrors `PlayerTally.of` (lib/domain/scoring/player_stats.dart) and
 * `CareerAggregator.contributionsFrom` (lib/domain/career/career_stats.dart)
 * — the Dart aggregator was written to compute exactly this shape but has
 * never been reachable from the JS Cloud Function that is the only writer
 * of `career_stats`. This file is the JS side of the same computation,
 * duplicated deliberately for the same reason `contribution.js` duplicates
 * `match_award.dart`: the server has to be the only writer, and both
 * languages need the shape to be independently testable.
 */

/** The key every scoring engine writes its per-player tallies under. Mirrors `PlayerTally.stateKey`. */
const TALLY_KEY = 'players';

/** One player's raw tally from a match's score state. Mirrors `PlayerTally.of`. */
export function playerTally(scoreState, playerId) {
  const all = (scoreState && scoreState[TALLY_KEY]) || {};
  const mine = all[playerId] || {};
  const out = {};
  for (const [k, v] of Object.entries(mine)) {
    if (typeof v === 'number') out[k] = v;
  }
  return out;
}

/**
 * Every registered player's tally from one finished match, keyed by uid.
 *
 * Guests (a lineup entry with no `uid`) are skipped, exactly as
 * `CareerAggregator.contributionsFrom` skips them — a borrowed player who
 * has never installed the app has no career to credit.
 */
export function playerTalliesByUid(scoreState, lineupA, lineupB) {
  const out = new Map();
  for (const p of [...(lineupA || []), ...(lineupB || [])]) {
    if (!p || !p.uid) continue;
    const tally = playerTally(scoreState, p.id);
    if (Object.keys(tally).length === 0) continue;
    out.set(p.uid, tally);
  }
  return out;
}

/**
 * Every counter moved by anyone on either side, summed into one map — a
 * club's contribution to its own career tally for this match.
 *
 * Sums both sides deliberately, and does not require a `uid`: a club's own
 * internal match (its own two teams playing each other) still moved real
 * counters, and "how many runs has this club's cricket ever produced"
 * counts everyone who was fielded, guests included — unlike a personal
 * career, a club's tally is not tied to any one account.
 */
export function clubTallyForMatch(scoreState, lineupA, lineupB) {
  const totals = {};
  const all = (scoreState && scoreState[TALLY_KEY]) || {};
  for (const p of [...(lineupA || []), ...(lineupB || [])]) {
    if (!p) continue;
    const mine = all[p.id] || {};
    for (const [k, v] of Object.entries(mine)) {
      if (typeof v !== 'number') continue;
      totals[k] = (totals[k] || 0) + v;
    }
  }
  return totals;
}
```

/// A club's record in one sport, accumulated across every match it has
/// hosted — the club-scoped counterpart to `CareerStats`.
///
/// Carries no `won`/`lost`/`drawn`: a fixture's `orgId` does not tell you
/// whether the match was this club against an outside opponent or two of
/// its own teams playing each other, so a club-level win/loss would often
/// be meaningless. See the design doc, "Club Won/Lost is out of scope".
/// `matchesPlayed` and `tally` are unambiguous regardless of who the
/// opponent was, so both are tracked from day one.
class OrgCareerStats {
  const OrgCareerStats({
    required this.orgId,
    required this.sportId,
    required this.matchesPlayed,
    required this.tally,
    this.lastPlayedAt,
  });

  final String orgId;
  final String sportId;
  final int matchesPlayed;

  /// Lifetime totals, keyed exactly as the sport's engine keys them —
  /// summed across every player who represented this club, both sides of
  /// every match. See `functions/career.js`'s `clubTallyForMatch`.
  final Map<String, num> tally;

  final DateTime? lastPlayedAt;

  num operator [](String key) => tally[key] ?? 0;

  /// Reads a club career-stats document back.
  ///
  /// [docId] is the sport id, because the write path stores one document
  /// per sport at `orgs/{orgId}/career_stats/{sportId}`. The document id is
  /// trusted over any `sportId` field for the same reason `CareerStats`
  /// does: a mismatched field would silently merge two sports' totals.
  ///
  /// [lastPlayedAt] is passed in already decoded — this file must not
  /// import `cloud_firestore`, or the domain layer stops being testable
  /// without a Firebase harness, exactly as `CareerStats.fromMap` requires.
  factory OrgCareerStats.fromMap(
    Map<String, dynamic>? d,
    String docId, {
    required String orgId,
    DateTime? lastPlayedAt,
  }) {
    final data = d ?? const <String, dynamic>{};
    final rawTally = data['tally'];
    return OrgCareerStats(
      orgId: orgId,
      sportId: docId,
      matchesPlayed: data['matchesPlayed'] is num
          ? (data['matchesPlayed'] as num).toInt()
          : 0,
      tally: rawTally is Map
          ? {
              for (final e in rawTally.entries)
                if (e.key is String && e.value is num)
                  e.key as String: e.value as num,
            }
          : const {},
      lastPlayedAt: lastPlayedAt,
    );
  }
}

  /// Key inside a player's or a club's `tally` map (see `CareerStats.tally`
  /// / `OrgCareerStats.tally`).
  final String key;

  final String label;

/// Which tally keys count as leaderboard-worthy, per sport — at most two,
/// most important first.
///
/// Declared once here rather than derived from each scoring plugin's box
/// score, because cricket — the sport with the richest box score — builds
/// its own bespoke scorecard and never populates a `StatColumn` at all (see
/// `CareerStats`'s own doc on why the shared per-player tally, not
/// `StatColumn`, is the one shape every sport's engine actually shares).
///
/// Sports absent from this map have no meaningful single leaderboard
/// number and are deliberately left out rather than forced into one:
/// - Mind sports (chess, carrom) — a raw counting stat does not capture
///   what "leading" means the way it does for a goal or a run.
/// - Performance sports (athletics, swimming) — these measure a personal

    HeadlineStat(key: 'assists', label: 'Assists'),
  ],
  'hockey': [

  ],
  'basketball': [

  ],
  'kabaddi': [

  ],
  'kho_kho': [

  ],
  'throwball': [
    HeadlineStat(key: 'pointsWon', label: 'Points won'),
  ],
  'volleyball': [

import 'package:flutter/material.dart';

/// Renders a `tally` map (`CareerStats.tally` / `OrgCareerStats.tally`) as a
/// sorted, humanized chip list — `raidPoints: 40` becomes a "Raid points 40"
/// chip. Shared by the player profile, the per-sport player page and the
/// club stats page, so a stat tally reads identically everywhere it appears.
class TallyChips extends StatelessWidget {
  const TallyChips({super.key, required this.tally, this.take});

  final Map<String, num> tally;

  /// Caps how many chips are shown, largest first — a profile card wants
  /// the top few; a dedicated stats page wants the full list (pass null).
  final int? take;

  @override
  Widget build(BuildContext context) {
    final theme = Theme.of(context);
    final entries = tally.entries.where((e) => e.value != 0).toList()
      ..sort((a, b) => b.value.abs().compareTo(a.value.abs()));
    final shown = take == null ? entries : entries.take(take!);

    return Wrap(
      spacing: 8,
      runSpacing: 8,
      children: [
        for (final e in shown)
          Chip(
            visualDensity: VisualDensity.compact,
            side: BorderSide.none,
            backgroundColor: theme.colorScheme.surfaceContainerHighest,
            label: Text(
              '${_humanize(e.key)} ${_format(e.value)}',
              style: theme.textTheme.bodySmall,
            ),
          ),
      ],
    );
  }

  static String _format(num v) =>
      v is int || v == v.roundToDouble() ? '${v.round()}' : v.toStringAsFixed(2);

  /// `raidPoints` → `Raid points`.
  static String _humanize(String key) {
    final spaced = key.replaceAllMapped(
      RegExp(r'(?<=[a-z0-9])(?=[A-Z])'),
      (_) => ' ',
    );
    return spaced[0].toUpperCase() + spaced.substring(1).toLowerCase();
  }
}

/**
 * Global stat leaderboards ("Orange Cap" style) — the JS mirror of Dart's
 * `sportHeadlineStats` (lib/domain/career/headline_stats.dart). Same
 * duplication trade as `contribution.js`: the server has to be the only
 * writer, and both languages need the key list to render/build against.
 */

import { FieldValue, getFirestore } from 'firebase-admin/firestore';
import { HttpsError, onCall } from 'firebase-functions/v2/https';
import { onSchedule } from 'firebase-functions/v2/scheduler';
import { logger } from 'firebase-functions';

/** Mirrors `sportHeadlineStats` — see that file for why each entry is here and why some sports have none. */
export const HEADLINE_STATS = {
  cricket: ['runsScored', 'wickets'],
  football: ['goals', 'assists'],
  hockey: ['goals'],
  basketball: ['points', 'rebounds'],
  kabaddi: ['raidPoints', 'tacklePoints'],
  kho_kho: ['touchPoints'],
  throwball: ['pointsWon'],
  volleyball: ['kills', 'aces'],
  tennis: ['pointsWon', 'aces'],
  table_tennis: ['pointsWon'],
  badminton: ['pointsWon'],

/**
 * Builds top-50 leaderboard documents, one per (sport, stat) pair. Pure —
 * takes already-loaded, already-privacy-filtered candidate rows and returns
 * the documents to write. Mirrors `buildBoards` in `talent.js`.
 */
export function buildLeaderboards(candidatesBySport) {
  const docs = [];
  for (const [sportId, statKeys] of Object.entries(HEADLINE_STATS)) {
    const candidates = candidatesBySport[sportId] || [];
    for (const statKey of statKeys) {
      const ranked = candidates
        .map((c) => ({
          uid: c.uid,
          displayName: c.displayName,
          value: (c.tally && c.tally[statKey]) || 0,
        }))
        .filter((e) => e.value > 0)
        .sort((a, b) => b.value - a.value)
        .slice(0, 50)
        .map((e, i) => ({ ...e, rank: i + 1 }));

      if (ranked.length === 0) continue;
      docs.push({
        id: `${sportId}__${statKey}`,
        data: { sportId, statKey, entries: ranked },
      });
    }
  }
  return docs;
}

async function loadSportCandidates(sportId) {
  const snap = await db()
    .collectionGroup('career_stats')
    .where('sportId', '==', sportId)
    .get();

  const rows = snap.docs
    .map((d) => ({ uid: d.ref.parent.parent.id, tally: d.data().tally || {} }))
    .filter((r) => Object.values(r.tally).some((v) => typeof v === 'number' && v > 0));

  const out = [];
  await Promise.all(
    rows.map(async (row) => {
      const userSnap = await db().doc(`users/${row.uid}`).get();
      const u = userSnap.data();
      if (!u) return;

      // audiencesFor in talent.js. A minor is never published on a global,
      // ungated board, full stop, regardless of their visibility setting.
      if (u.profileVisibility !== 'public' || u.isMinor === true) return;
      out.push({ uid: row.uid, displayName: u.displayName || 'Player', tally: row.tally });
    }),
  );
  return out;
}

/** Batched write-and-prune. Mirrors `publishBoards` in talent.js exactly. */
async function publishLeaderboards(docs) {
  const keep = new Set(docs.map((d) => d.id));
  const collection = db().collection('leaderboards');

  let batch = db().batch();
  let queued = 0;
  const flush = async () => {
    if (queued === 0) return;
    await batch.commit();
    batch = db().batch();
    queued = 0;
  };

  for (const doc of docs) {
    batch.set(collection.doc(doc.id), {
      ...doc.data,
      computedAt: FieldValue.serverTimestamp(),
    });
    queued += 1;
    if (queued >= 400) await flush();
  }

  const existing = await collection.select().get();
  let removed = 0;
  for (const d of existing.docs) {
    if (keep.has(d.id)) continue;
    batch.delete(d.ref);
    removed += 1;
    queued += 1;
    if (queued >= 400) await flush();
  }
  await flush();
  return { written: docs.length, removed };
}

async function runStatLeaderboards() {
  const bySport = await loadAllCandidates();
  const docs = buildLeaderboards(bySport);
  const result = await publishLeaderboards(docs);
  logger.info(
    `computeStatLeaderboards: ${docs.length} boards written, ${result.removed} stale removed.`,
  );
  return result;
}

import { clubTallyForMatch } from './career.js';

/**
 * Recomputes every club's `career_stats` from scratch, from every finished
 * fixture the club has ever hosted. One-time use, run by hand after this
 * plan's Cloud Functions are deployed, so pre-launch match history is not
 * invisible on the new club-stats screens.
 *
 * MUST overwrite, not merge/increment — see the design doc's "backfill
 * idempotency" note. This computes an absolute, correct total from the
 * fixtures themselves; the live `onMatchSettled` trigger's own increments
 * for matches settled AFTER this runs still add correctly on top of that
 * baseline. Running this twice, or running it after some live matches
 * have already been settled, must not double-count — and it doesn't,
 * because each run recomputes the whole total independently rather than
 * adding to whatever is already there.
 *
 * @param {boolean} dryRun When true, computes and logs the totals but does
 *   not write them — for sanity-checking a couple of known clubs' numbers
 *   before trusting this to overwrite real data.
 */
async function runClubStatsBackfill({ dryRun = false } = {}) {
  const totals = new Map(); // `${orgId}::${sportId}` -> { matchesPlayed, tally }
  let fixturesScanned = 0;

  const orgsSnap = await db().collection('orgs').select().get();
  for (const orgDoc of orgsSnap.docs) {
    const orgId = orgDoc.id;
    const compsSnap = await db()
      .collection(`orgs/${orgId}/competitions`)
      .select()
      .get();

    for (const compDoc of compsSnap.docs) {
      const fixturesSnap = await db()
        .collection(`orgs/${orgId}/competitions/${compDoc.id}/fixtures`)
        .where('status', '==', 'completed')
        .get();

      for (const fixDoc of fixturesSnap.docs) {
        const f = fixDoc.data();
        const sportId = f.sportId ?? f.scoringPluginKey ?? 'unknown';
        const key = `${orgId}::${sportId}`;
        const cur = totals.get(key) || { matchesPlayed: 0, tally: {} };
        cur.matchesPlayed += 1;
        const matchTally = clubTallyForMatch(f.scoreState, f.lineupA, f.lineupB);
        for (const [k, v] of Object.entries(matchTally)) {
          cur.tally[k] = (cur.tally[k] || 0) + v;
        }
        totals.set(key, cur);
        fixturesScanned += 1;
      }
    }
  }

  if (dryRun) {
    const preview = [...totals.entries()].slice(0, 10).map(([key, t]) => ({
      key,
      matchesPlayed: t.matchesPlayed,
      tally: t.tally,
    }));
    logger.info(
      `backfillClubStats (dry run): ${fixturesScanned} fixtures scanned, ` +
        `${totals.size} club/sport records WOULD be written. First 10: ` +
        JSON.stringify(preview),
    );
    return { fixturesScanned, orgSportPairs: totals.size, dryRun: true, preview };
  }

  let batch = db().batch();
  let queued = 0;
  const flush = async () => {
    if (queued === 0) return;
    await batch.commit();
    batch = db().batch();
    queued = 0;
  };

  for (const [key, totalsForKey] of totals) {
    const [orgId, sportId] = key.split('::');
    // A plain `.set()` with no `{ merge: true }` replaces the whole
    // document — the deliberate "recompute from scratch" behaviour this
    // function's doc comment requires.
    batch.set(db().doc(`orgs/${orgId}/career_stats/${sportId}`), {
      orgId,
      sportId,
      matchesPlayed: totalsForKey.matchesPlayed,
      tally: totalsForKey.tally,
      lastPlayedAt: FieldValue.serverTimestamp(),
    });
    queued += 1;
    if (queued >= 400) await flush();
  }
  await flush();

  logger.info(
    `backfillClubStats: ${fixturesScanned} fixtures scanned, ` +
      `${totals.size} club/sport records written.`,
  );
  return { fixturesScanned, orgSportPairs: totals.size, dryRun: false };
}

/**

 * Pass `{ dryRun: true }` in the callable's data to preview counts first.
 */

    if (request.auth?.token?.admin !== true) {
      throw new HttpsError(
        'permission-denied',
        'Backfilling club stats is restricted to PlaySphere staff.',
      );
    }

  },
);

/// One row on a stat leaderboard — the "Orange Cap" idea, generalised
/// across every sport with a headline stat. See `HeadlineStat` for which
/// sports have one.
class LeaderboardEntry {
  const LeaderboardEntry({
    required this.uid,
    required this.displayName,
    required this.rank,
    required this.value,
  });

  final String uid;
  final String displayName;
  final int rank;
  final num value;

  static LeaderboardEntry? fromMap(Object? raw) {
    if (raw is! Map) return null;
    final uid = raw['uid'];
    if (uid is! String || uid.isEmpty) return null;
    return LeaderboardEntry(
      uid: uid,
      displayName: (raw['displayName'] as String?) ?? 'Player',
      rank: (raw['rank'] as num?)?.toInt() ?? 0,
      value: (raw['value'] as num?) ?? 0,
    );
  }
}

/// A whole leaderboard for one (sport, stat) pair — top 50, precomputed by
/// `functions/stats.js` on a nightly schedule. See the design doc for why
/// this is a scheduled rebuild rather than a live query.
class Leaderboard {
  const Leaderboard({
    required this.sportId,
    required this.statKey,
    required this.statLabel,
    required this.entries,
  });

  final String sportId;
  final String statKey;

  /// Passed in from `HeadlineStat.label` rather than read from the
  /// document — the document's own purpose is the ranked entries, and the
  /// label is already known by whatever screen asked for this board.
  final String statLabel;

  final List<LeaderboardEntry> entries;

  factory Leaderboard.fromMap(
    Map<String, dynamic>? d, {
    required String sportId,
    required String statKey,
    required String statLabel,
  }) {
    final data = d ?? const <String, dynamic>{};
    final rawEntries = data['entries'];
    return Leaderboard(
      sportId: sportId,
      statKey: statKey,
      statLabel: statLabel,
      entries: rawEntries is List
          ? [
              for (final e in rawEntries)
                if (LeaderboardEntry.fromMap(e) case final entry?) entry,
            ]
          : const [],
    );
  }
}

/// Reads a precomputed global leaderboard. A one-shot fetch rather than a
/// live listener — the board only changes on the nightly rebuild
/// (`computeStatLeaderboards`), so there is nothing for a snapshot listener
/// to usefully stay subscribed to between one screen open and the next.
class LeaderboardRepository {
  const LeaderboardRepository();

  Future<Leaderboard?> fetch(String sportId, String statKey, String statLabel) async {
    final snap = await Refs.leaderboard(sportId, statKey).get();
    if (!snap.exists) return null;
    return Leaderboard.fromMap(
      snap.data(),
      sportId: sportId,
      statKey: statKey,
      statLabel: statLabel,
    );
  }
}

/// tally, its own leaders for the sport's headline stat, and every finished
/// match — each opening the same scorecard-and-memories screen a player's

class ClubSportStatsScreen extends ConsumerWidget {

        .watch(clubSportFixturesProvider((orgId: orgId, sportId: sportId)));

    return Scaffold(

          return ListView(

          );
        },
      ),

/// This club's own headline number, plus a link out to the app-wide board.
/// See the design doc: "Both, club page links out to global" was the
/// explicit choice over club-only or global-only leaderboards.
class _TopScorers extends StatelessWidget {
  const _TopScorers({required this.sportId, required this.line});

  final String sportId;
  final OrgCareerStats? line;

  @override
  Widget build(BuildContext context) {
    final stat = primaryHeadlineStat(sportId);
    if (stat == null) return const SizedBox.shrink();
    final value = line?[stat.key] ?? 0;
    final formatted =
        value == value.roundToDouble() ? '${value.round()}' : value.toStringAsFixed(2);

    return Column(
      crossAxisAlignment: CrossAxisAlignment.stretch,
      children: [
        SectionHeader(
          icon: Icons.emoji_events_outlined,
          title: '${stat.label} leaders',
          subtitle: "This club's all-time total.",
        ),
        Card(
          child: ListTile(
            title: Text('${stat.label}: $formatted'),
            subtitle: const Text(
              'Combined across every player who has represented this club.',
            ),
            trailing: TextButton(
              onPressed: () => context.push(
                Routes.leaderboard(sportId.split(':').first, stat.key),
              ),
              child: const Text('Full leaderboard'),
            ),
          ),
        ),
      ],
    );
  }
}

class _Matches extends StatelessWidget {
  const _Matches({required this.uid, required this.fixtures});

  final String uid;
  final AsyncValue<List<Fixture>> fixtures;

  @override
  Widget build(BuildContext context) {
    if (fixtures.isLoading) {
      return const Padding(
        padding: EdgeInsets.symmetric(vertical: 24),
        child: Center(child: CircularProgressIndicator()),
      );
    }
    final list = fixtures.valueOrNull ?? const <Fixture>[];
    if (list.isEmpty) {
      return const Card(
        child: ListTile(
          leading: Icon(Icons.sports_score_outlined),
          title: Text('No matches recorded'),
          subtitle: Text('Matches in this sport will collect here.'),
        ),
      );
    }
    return Column(
      children: [for (final f in list) PlayerMatchTile(fixture: f, uid: uid)],
    );
  }
}

import 'package:flutter/material.dart';

/// The app-wide "Orange Cap" board for one sport's headline stat — top 50,
/// precomputed nightly. See the design doc for why this is not a live
/// query.
class LeaderboardScreen extends ConsumerWidget {
  const LeaderboardScreen({
    super.key,
    required this.sportId,
    required this.statKey,
  });

  final String sportId;
  final String statKey;

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final sport = SportCatalog.byId(sportId.split(':').first);
    final stat = sportHeadlineStats[sportId.split(':').first]
        ?.where((s) => s.key == statKey)
        .firstOrNull;
    final statLabel = stat?.label ?? statKey;

    final board = ref.watch(leaderboardProvider(
      (sportId: sportId, statKey: statKey, statLabel: statLabel),
    ));

    return Scaffold(
      appBar: AppBar(title: Text('${sport.name} · $statLabel leaders')),
      body: AsyncView(
        value: board,
        onRetry: () => ref.invalidate(leaderboardProvider(
          (sportId: sportId, statKey: statKey, statLabel: statLabel),
        )),
        builder: (leaderboard) {
          final entries = leaderboard?.entries ?? const [];
          if (entries.isEmpty) {
            return const EmptyState(
              icon: Icons.emoji_events_outlined,
              title: 'No leaderboard yet',
              message:
                  'This board fills in after the next nightly rebuild, once '
                  'enough matches have been played.',
            );
          }
          return ListView(
            padding: const EdgeInsets.all(16),
            children: [
              ContentBounds(
                maxWidth: 700,
                child: Card(
                  child: Column(
                    children: [
                      for (final e in entries)
                        ListTile(
                          leading: SizedBox(
                            width: 32,
                            child: Text(
                              '${e.rank}',
                              textAlign: TextAlign.center,
                              style: Theme.of(context).textTheme.titleSmall,
                            ),
                          ),
                          title: Text(e.displayName),
                          trailing: Text(
                            '${e.value}',
                            style: Theme.of(context).textTheme.titleMedium,
                          ),
                          onTap: () => context.push(Routes.profile(e.uid)),
                        ),
                    ],
                  ),
                ),
              ),
            ],
          );
        },
      ),
    );
  }
}
